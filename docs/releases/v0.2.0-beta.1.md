# DotDoctor 0.2.0-beta.1

First public pre-release of DotDoctor's Arch Linux / CachyOS maintenance CLI.
The release tag is `v0.2.0-beta.1`; Python package metadata and `dotdoctor version`
use `0.2.0b1`.

## Three modes

| Command | Purpose |
| --- | --- |
| `dotdoctor` | Parallel system audit with live results and follow-up action prompts. |
| `dotdoctor --sysup` | Sequential updates with preflight checks and configured snapshots. |
| `dotdoctor --fix` | Confirmed hygiene actions followed by verification. |

## Highlights

- Update checks for pacman, AUR, Flatpak and firmware, plus package/cache/config
  checks, failed services, disk space, scheduled maintenance and optional storage
  and security readers.
- Immediate results in fixed rows, with cancellable audit process groups and
  static output for pipes or animation opt-outs.
- Snapshot and package-transaction failures stop the update workflow. Signing-key
  preparation, Arch notice review and manager-specific Yay/Paru commands are included.
- Sudo authentication stays outside spinners. Captured cleanup output prevents
  password prompts and pacman progress bars from being overwritten.
- Backup monitoring is opt-in. Active timers without completion history and
  advisories without fixed-version data use neutral SKIP, with details in `-v`
  and JSON. Confirmed failures remain actionable; unverified results are not PASS.

## Install

Requires Linux and Python 3.11+. In a virtual environment, install the attached wheel:

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install https://github.com/m1tyarch/DotDoctor/releases/download/v0.2.0-beta.1/dotdoctor-0.2.0b1-py3-none-any.whl
dotdoctor version
dotdoctor --help
```

The release includes a wheel, source distribution and `SHA256SUMS`.
After downloading the three files, verify the archives with `sha256sum -c SHA256SUMS`.
Runtime integrations depend on installed system tools; see the
[README](https://github.com/m1tyarch/DotDoctor/blob/v0.2.0-beta.1/README.md) and
[reference](https://github.com/m1tyarch/DotDoctor/blob/v0.2.0-beta.1/docs/reference.md).
The `dotdoctor-git` AUR recipe is available in the repository but has not been
published to AUR. This release does not publish a PyPI package.

## Migration from the 0.1.0 development MVP

- `scan`, `--env`, `--sys`, `--profile` and development profiles have been removed.
  Use the three commands above. Configurations containing only `disabled_checks`
  continue to work.
- Audit/fix exit code 0 includes WARN, OUTD and SKIP; FAIL returns 2. Use JSON
  results when automation needs stricter policy. JSON export is available for
  audit/fix modes, with `OUTD` corresponding to terminal `OLD`.
- Configure `maintenance.backup` only to monitor an existing backup adapter;
  DotDoctor does not create a backup repository or enable backup monitoring by default.

## Validation and coverage

- 435 unit/integration tests pass. Local Python 3.14.8 coverage is 89.41%, above
  the 75% CI requirement. Ruff, Black and mypy pass.
- GitHub CI validates the release commit on Python 3.11, including clean wheel
  and sdist installations. Both artifacts were also installed independently on
  Python 3.14.8; dependencies, all module imports, help and version were checked.
- Automated system interactions use mocks. The owner has exercised earlier
  commits on a workstation and a fresh headless Arch VM, providing the regressions
  covered by this release. The exact release has not been certified across a
  hardware/filesystem matrix; snapshots, firmware, SMART and Btrfs integrations
  are covered by mocked scenarios in the release checks.

This is a beta for early feedback. A report describes checks actually performed;
it does not guarantee complete system security or recoverability. Cancelling a
package transaction does not roll it back, and snapshots do not replace an
independent verified backup. Audit follow-up prompts default to yes; enter `n`
to keep the run diagnostic.

Please include `dotdoctor version`, the command used, and its output when
[reporting an issue](https://github.com/m1tyarch/DotDoctor/issues).
